# Automated Encrypted Offsite Backup Runbook

This document defines the operational runbook, security policies, storage configurations, and recovery procedures for the Elimara School OS automated offsite PostgreSQL backup pipeline.

---

## 1. Overview & Architecture

Elimara uses a multi-layered disaster recovery architecture:
- **Layer 1 (Continuous Operational Recovery)**: Neon continuous WAL Point-in-Time Recovery (PITR) for near-instantaneous branch recovery within the primary cloud infrastructure.
- **Layer 2 (Offsite Disaster Recovery)**: Automated logical backups (`pg_dump`), compressed with `gzip`, encrypted on the client side with **AES-256-GCM**, and streamed to an independent S3-compatible private object store (**Cloudflare R2** or **Amazon S3**).

```
┌────────────────────────────────┐
│ Neon Serverless PostgreSQL     │
│ (Primary Production Database)  │
└───────────────┬────────────────┘
                │ TLS 1.3 (DIRECT_URL)
                ▼
┌────────────────────────────────┐
│ Isolated Backup Worker         │
│ (Scheduled Cron / Runner)      │
│ 1. pg_dump logical stream      │
│ 2. gzip (level 9) compression  │
│ 3. Client-side AES-256-GCM     │
│ 4. Compute SHA-256 digest      │
└───────────────┬────────────────┘
                │ HTTPS (S3 API - PutObject / Multipart)
                ▼
┌────────────────────────────────────────────────────────┐
│ Cloudflare R2 / Amazon S3 (Dedicated Private Bucket)   │
│ - Public Access Blocked                                │
│ - SSE-S3 / SSE-KMS at rest                             │
│ - Path: backups/YYYY/MM/elimara-backup-<TS>.dump.gz.enc│
│ - Manifest: elimara-backup-<TS>.manifest.json          │
└────────────────────────────────────────────────────────┘
```

## 2. Security & Threat Mitigation

### 2.1 Encryption Standards
- **In Transit**: Enforced TLS 1.3 for database connection and HTTPS for S3 API endpoints.
- **Client-Side Encryption (Envelope)**:
  - Algorithm: **AES-256-GCM** (Galois/Counter Mode).
  - Initialization Vector (IV): Cryptographically secure random 16-byte IV generated per backup.
  - Authentication Tag: 16-byte authentication tag generated by the cipher to prevent ciphertext tampering.
  - Key Management: 256-bit key supplied via environment variable `BACKUP_ENCRYPTION_KEY` injected at runtime from cloud secrets manager.
- **Server-Side Encryption (At Rest)**:
  - Enabled by default on Cloudflare R2 and Amazon S3.

### 2.2 Least-Privilege Storage IAM Policy
The storage credential used by the backup worker must have only the minimum permissions required:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowElimaraBackupUploadAndVerify",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:ListBucket",
        "s3:AbortMultipartUpload"
      ],
      "Resource": [
        "arn:aws:s3:::elimara-db-backups-private",
        "arn:aws:s3:::elimara-db-backups-private/*"
      ]
    }
  ]
}
```

> [!CAUTION]
> Strictly deny `s3:DeleteBucket`, `s3:PutBucketPolicy`, and `s3:PutBucketAcl`. Never permit public read access.

## 3. Required Environment Variables

All secrets must be injected via the deployment platform's secret manager (e.g., GitHub Secrets, AWS Secrets Manager, Doppler, or Cloudflare Secrets).

| Variable Name | Required | Description | Example / Format |
|---|:---:|---|---|
| `BACKUP_DATABASE_URL` | Yes | Direct connection string to PostgreSQL (migration or backup role) | `postgresql://user:pass@host:5432/neondb?sslmode=require` |
| `BACKUP_ENCRYPTION_KEY` | Yes | 256-bit hexadecimal key for client-side AES-256-GCM encryption | 64-character hex string |
| `BACKUP_S3_ENDPOINT` | Yes | S3-compatible API endpoint URL | `https://<account_id>.r2.cloudflarestorage.com` or `https://s3.us-east-2.amazonaws.com` |
| `BACKUP_S3_REGION` | Yes | S3 storage region (`auto` for Cloudflare R2) | `auto` or `us-east-2` |
| `BACKUP_S3_BUCKET` | Yes | Name of private target bucket | `elimara-db-backups-private` |
| `BACKUP_S3_ACCESS_KEY_ID` | Yes | Storage service access key ID | String |
| `BACKUP_S3_SECRET_ACCESS_KEY` | Yes | Storage service secret access key | String |
| `BACKUP_S3_PREFIX` | No | Prefix / folder in bucket (default: `backups/`) | `backups/` |
| `BACKUP_RETENTION_DAYS` | No | Retention period for standard daily backups (default: `30`) | `30` |

## 4. Cadence, Naming, and Retention Lifecycle

### 4.1 Backup Cadence
- **Automated Schedule**: Daily at 02:00 UTC (off-peak school hours).
- **Ad-Hoc / Pre-Deployment**: Operator-triggered before major schema migrations.

### 4.2 Naming Convention
- Backup Artifact: `backups/YYYY/MM/elimara-backup-YYYY-MM-DDTHH-mm-ssZ.dump.gz.enc`
- Backup Manifest: `backups/YYYY/MM/elimara-backup-YYYY-MM-DDTHH-mm-ssZ.manifest.json`

### 4.3 Retention Tiers
- **Daily Backups**: Retained for 30 days.
- **Weekly Backups (Sundays)**: Retained for 90 days.
- **Monthly Backups (1st of month)**: Retained for 365 days (or archived to cold/Glacier storage for 7-year statutory financial compliance).
- **Multipart Upload Abort**: Incomplete multipart uploads automatically pruned after 7 days via S3 lifecycle configuration.

## 5. Operator Runbook

### 5.1 Trigger an Immediate Manual Backup
To manually trigger a backup (e.g. before a major release):

```bash
pnpm --filter @elimara/database run db:backup:create
```

### 5.2 Verify Latest Backup Integrity
Downloads the latest encrypted backup artifact from S3, checks SHA-256 digest against the manifest, verifies the AES-256-GCM authentication tag, and confirms the gzip stream is valid without writing unencrypted data to disk:

```bash
pnpm --filter @elimara/database run db:backup:verify
```

### 5.3 Restore an Offsite Backup into an Isolated Database
Downloads the specified (or latest) backup, decrypts it in-memory, and restores the logical SQL schema and data into a designated disposable target:

```bash
TARGET_DATABASE_URL="postgresql://user:pass@ep-isolated-restore.neon.tech/neondb?sslmode=require" \
  pnpm --filter @elimara/database run db:backup:restore
```

After restoration, execute the database validation suite to verify complete consistency:
```bash
RESTORED_DATABASE_URL="$TARGET_DATABASE_URL" \
  pnpm --filter @elimara/database run db:verify:restore
```

## 6. S3 / R2 Bucket Setup Instructions

1. **Cloudflare R2**:
   - Create bucket `elimara-db-backups-private`.
   - Ensure **Public Access** is disabled.
   - Generate an **R2 API Token** with `Object Read & Write` permissions scoped exclusively to `elimara-db-backups-private`.
2. **Amazon S3**:
   - Create bucket `elimara-db-backups-private` with **Block all public access** enabled.
   - Enable **Default encryption** (Amazon S3 managed keys SSE-S3 or AWS KMS).
   - Configure Lifecycle Rule:
     - Rule name: `abort-incomplete-multipart-uploads`
     - Action: Clean up incomplete multipart uploads after 7 days.
